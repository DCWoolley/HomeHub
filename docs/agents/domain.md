# Domain docs

## Layout

This repo uses one root GLOSSARY.md and root docs/adr/.

## Before exploring domain behaviour

Read GLOSSARY.md and any ADRs relevant to the area being changed.
If either is absent, proceed silently. Create domain documentation
lazily when terms or meaningful architectural decisions are resolved.

## Vocabulary and decisions

Use the glossary's canonical terms in code, tests, issues, and docs.
Surface conflicts with existing ADRs rather than silently overriding them.
